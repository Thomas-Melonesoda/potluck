# potluck roadmap

This is the single source of progress for potluck. Agents read it before starting work and update it in the same PR that finishes a step. The owner's original wording for each decision is kept privately; [`tools/forks.json`](../tools/forks.json) carries the English paraphrase.

Status values: **done**, **in progress**, **not started**.

## Stage 3: align with pstack where pstack-claude differs (done, 2026-11-22)

- Merging and autopilot (S3-A1, S3-A3, S3-A6, S3-A8, S3-A11, S3-C4): each owner merges its own verified PR without waiting for a person, through the deterministic merge gate [`merge-gate.mjs`](../plugins/pstack/skills/poteto-mode/scripts/merge-gate.mjs) (the verifier's `potluck/verdict` commit status, green CI, `--match-head-commit`, never `--auto`); two fix-forwards per PR, then the root agent picks a fresh owner, a split, or a parked draft; an owner rebases a conflict-free branch itself ([#8](https://github.com/Thomas-Melonesoda/potluck/pull/8), [#9](https://github.com/Thomas-Melonesoda/potluck/pull/9), [#11](https://github.com/Thomas-Melonesoda/potluck/pull/11)). The quality floor inside the gate moves to stage 4 with `CONSTRAINTS.md`.
- Evidence, parallel worktrees, session pickup, foreground routing, and review follow pstack-claude (the S3-B, S3-D, S3-E, and S3-F rows in [decisions](decisions.md)). Principle skills (S3-E4) load by model invocation in every harness; Claude Code and Muse hide them from the `/` menu; in other harnesses they may appear there, which is untested.
- Worktree cleanup (S3-C3): [`worktree-backup.mjs`](../plugins/pstack/skills/poteto-mode/scripts/worktree-backup.mjs) backs a worktree up before removal (tracked edits to a local `backup/` branch, untracked and ignored files, and the raw copy of each changed or filtered tracked file, to a trash tarball kept 30 days, HEAD-only and reflog-only commits to branches), and the cleanup playbook runs it on every worktree and then deletes without asking. A worktree with a lock, an initialized submodule or a submodule repository in its git dir, an operation in progress, skip-worktree or assume-unchanged files on disk, unmerged paths, or no commit is held and reported instead, because removal there could lose work the backup cannot save ([#10](https://github.com/Thomas-Melonesoda/potluck/pull/10)).
- pstack's usage guide (S3-G1) is a synced component at [`docs/guide`](guide/README.md), with a Chinese translation at [`docs/guide-zh-CN`](guide-zh-CN/README.md) that a test keeps in step with each English page ([#12](https://github.com/Thomas-Melonesoda/potluck/pull/12), [#13](https://github.com/Thomas-Melonesoda/potluck/pull/13)). `automations/` and `make-bot-ui` stay out (S3-G2, S3-G3); no telemetry.

## Stage 6: the stage 5 design answers (in progress)

The owner ruled on all 17 issues from stage 5 (2026-11-23). potluck's defaults keep Lauren's way; a new operator's gates file holds settings stricter than the defaults, for one user or one repository.

- Register: every row carries its step (`S3-A1`, `S4-G1`), entries may carry a Chinese note (`ruling_zh`) that `docs/decisions.md` shows under the English ruling, and the forked Addy Osmani file is `kind: borrow`.
- Operator's gates: done ([#39](https://github.com/Thomas-Melonesoda/potluck/pull/39), [#44](https://github.com/Thomas-Melonesoda/potluck/pull/44)). [`operator-gates.md`](operator-gates.md) explains the file, `~/.potluck/gates.json` plus a repository's `.potluck/gates.json`, the stricter value winning. The merge gate tells a PR with no checks from one whose checks failed: no checks merges on its verdict by default, waits for CI that a check suite shows is coming, and is held for a person under `noCI: "wait"` or when the PR changes its workflows. Under `foreignRepos: "ask"`, Claude Code's Bash hook asks before a `gh` write in a repository that neither the `gh` account nor its organizations own. poteto-mode reads the gates when a run starts.
- Quality floor: done ([#36](https://github.com/Thomas-Melonesoda/potluck/pull/36), [#43](https://github.com/Thomas-Melonesoda/potluck/pull/43)). The floor guard reads every file that runs and leaves only plain `.md` unchecked, a list a test pins to the register; CONSTRAINTS.md's rule checks always run, and a repository's first CONSTRAINTS.md may carry exceptions, so the skill's template passes as written. Rule names must be unique, either colon ends one, and Chinese bar words can only add threshold findings to main's English reading. Swift tests, XCTSkip, and a test step removed from CI count. A test only renamed, with the same content, folder and naming form, passes, and a changed or moved assertion waits for the root agent's co-sign, a `potluck/cosign` status bound to the head and a row in its decision log.
- Git guardrail: force pushes and worktree cleanup ([#33](https://github.com/Thomas-Melonesoda/potluck/pull/33), [#38](https://github.com/Thomas-Melonesoda/potluck/pull/38), [#42](https://github.com/Thomas-Melonesoda/potluck/pull/42), [#45](https://github.com/Thomas-Melonesoda/potluck/pull/45)). The hook blocks a force push to a default branch (the remote's default, `main`, or `master`), lease or not, and a remote branch deletion, even in a clean repository; a forced push passes only when every branch it writes can be read and none is a default branch, so a lease push of the agent's own branch passes. Spellings it does not follow, such as git aliases, `git -c` overrides, and branch names piped through `xargs`, are listed in #45. Worktree cleanup runs `worktree-remove.mjs`, which refuses any path but the top level of a linked worktree, checks the backup branches and tarball against the worktree, and moves the worktree to a trash cleared after 30 days instead of deleting it. When it blocks over uncommitted work, its advice is to commit the files the task touched, by name, not `git add -A` ([#41](https://github.com/Thomas-Melonesoda/potluck/pull/41)); the one assertion that pinned the old advice was retired through stage 5 issue 17's co-sign.
- Handoffs: done ([#35](https://github.com/Thomas-Melonesoda/potluck/pull/35), [#40](https://github.com/Thomas-Melonesoda/potluck/pull/40)). `resume.mjs` keeps one checkpoint pointer per folder and task and lists them, keeps a checkpoint for a folder outside Git in the folder or at a `--store` location, and records HEAD at each pause, so pickup rechecks the note when the branch moved. Pause safely has a checkpoint-and-keep-going mode that is not a pause, and poteto-mode and every session-start mandate route handoff requests in Chinese as well as English.
- New projects: done ([#34](https://github.com/Thomas-Melonesoda/potluck/pull/34)). When grill is done, its `scripts/starter.mjs` writes what a project lacks and never overwrites a file: CI that runs the project's check on every pull request and on main, a pre-commit hook with the quality floor and a gitleaks scan, and an AGENTS.md skeleton. The floor guard stays in the clone's git folder, because its own patterns would trip it in the tree.
- Eval: done ([#32](https://github.com/Thomas-Melonesoda/potluck/pull/32), [#37](https://github.com/Thomas-Melonesoda/potluck/pull/37)). `tools/eval.mjs` holds `evals/triggers.json` against the base in CI, so no setting may loosen and no `known` mark or allowed collision may be added. poteto-mode names what routes to domain-modeling, constraint-driven-development, and grill; Matt Pocock's domain-modeling description is a borrow and grill's is sharper, so 58.3% of positive cases rank first and the floor rises from 55 to 58.
