### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `skills/poteto-mode/scripts/worktree-audit.mjs` under the installed plugin (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or your own session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the session list. Pick each subagent's reasoning level for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked paths with uncommitted changes and `untracked:N` is N files git has never seen. A worktree with both prints both, as in `wip:1,untracked:5`. `ignored:N` is N paths git ignores outside the build and cache directories named in the audit's `DISPOSABLE` list, such as `.env` or `.claude/settings.local.json`, which may exist nowhere else. List them with `git -C <path> status --porcelain --ignored=matching`. Also run `git -C <path> submodule foreach --recursive 'git ls-files --others --ignored --exclude-standard --directory --no-empty-directory'` to list ignored paths inside initialized submodules. `reflog:N` is N commits that no branch, tag, or remote reaches, kept only by the worktree's HEAD and its reflog, such as work committed on a detached HEAD. They are among the entries `git -C <path> reflog` prints. Keep any with `git branch <name> <sha>`. A clean worktree is recoverable from its branch. Either kind of uncommitted work is gone once the directory goes, so list it with the call the audit counted from, `git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none`, show the diff from `git -C <path> diff HEAD --ignore-submodules=none --submodule=log`, and back it up as below before the directory goes. Each status line is work at stake, and an empty diff never means there is none. A diff leaves out every untracked file, and a plain `git diff` can leave out a submodule. A `wip` line that names a submodule stands for files changed or added inside it, or for commits made there. Run the same status call inside the submodule to list those files. `hold-locked` means another tool or agent locked the tree, with its reason in the LOCKED column. `git worktree remove` refuses a locked tree, so do not `rm -rf` around it.

   Back up instead of asking. For every worktree in the confirmed set, clean ones included, run `node` on `skills/poteto-mode/scripts/worktree-remove.mjs` under the installed plugin with the path `git worktree list` prints for it. It refuses any other path (the main checkout, a folder inside a worktree, anything outside every worktree). It runs `worktree-backup.mjs` first, which saves tracked edits, staged and on disk, as wip commits on a local `backup/<name>-<date>` branch, packs every untracked file, the ignored files outside build and cache directories (such as `.env`), and the on-disk copy of each changed tracked file and of every tracked file with a clean filter (which can alter what git stores) into a tarball under `~/.potluck/trash/<date>/` (kept 30 days, `--keep-days` or `POTLUCK_TRASH_DAYS` to change), and branches any commit only HEAD or its reflog reaches, without touching the worktree. The audit cannot see every risk the backup checks, so a worktree the audit calls clean still runs it. Then it checks the backup: each backup branch exists at the commit the backup made, and the tarball holds the same files, at the same sizes, as the worktree on disk. Only then does it move the worktree into the trash's date folder, never `rm -rf`, and drop git's record of that one worktree. A recorded `removed` result is the agent's deletion, made without asking. Never push a `backup/` branch, since the wip commit can hold work the user never meant to publish. A `hold` result (a backup that does not match the worktree, or a trash on another volume; a locked tree; any initialized submodule, files in an uninitialized submodule's folder, or a submodule repository left in the worktree's git dir; a rebase, merge, cherry-pick, revert, or bisect in progress; skip-worktree or assume-unchanged files on disk; unmerged paths; or a worktree with no commit yet), a run that exits with an error, and an in-use tree are skipped, not deleted, and listed in the reply.
5. Prune nothing by hand. Each `removed` result already moved its worktree to the trash and dropped git's record of it. Never `git worktree remove --force` or `rm -rf` a worktree, what is left of one, or a trash folder: the backup clears date folders older than its retention. Branch refs survive, so commits on the worktree's branch are kept. The worktree's HEAD reflog goes with it, so a commit only that reflog reaches is lost. Commits made inside a submodule are stored with the worktree and go with it. Confirm with `df -h /` and re-list. A moved worktree's space frees only when its trash folder expires.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, your editor's application-support caches, `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/shell-snapshots/` and old `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/` transcripts (keep the recent ones the **recall** skill and Session pickup read), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees removed with where each one went (backup branch names, tarball path, and trash folder), each expired trash folder listed under `trashNotCleared` with its error, for the user to clear, and a one-line reason for each held back (in-use by which chat, or the backup's hold reason).
